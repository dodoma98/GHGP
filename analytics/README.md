> ## ⚠ 2026-09-22 — 이 집계는 **더 이상 쓰지 않습니다**
>
> 방문·조회는 이제 **그린홈시스 지원 콘솔**(마케팅 메뉴)에서 봅니다. 사이트에 붙는 줄도
> `https://gh-point.com/track.js` 한 줄로 바뀌었고, 이 폴더의 코드는 각 사이트에서 걷어냈습니다.
> 바꾼 까닭은 «방문 대비 문의» 때문입니다 — 견적·상담 자료가 그쪽 DB 에 있어야 한 화면에서
> 같이 볼 수 있습니다(임송화 결정 2026-09-22 "콘솔로 모은다").
>
> **여기 적힌 것을 새로 설치하지 마세요.** 이 글과 `worker.js`·`schema.sql` 을 남겨 두는 것은
> ① Cloudflare 에 이미 쌓인 지난 기록을 볼 방법이 이 대시보드뿐이고 ② 그때 무엇을 어떻게
> 셌는지가 여기에만 적혀 있어서입니다. 옮겨 온 것: 쪽 조회 · 버튼 클릭(전화·자료·견적·거래처·
> 포인트·숨고·블로그·영상) · `?notrack=1` 기기 제외(옛 설정도 그대로 지킵니다).
> 안 옮긴 것: `?selftest=1` 자가 진단, 예비 주소 자동 전환.

# 그린홈시스 방문 집계 · 대시보드 설치 안내

우리 사이트들의 방문 기록을 **직접 집계**해서, 관리자만 볼 수 있는 대시보드 하나에서 확인하는 구성입니다.
외부 분석 서비스를 쓰지 않고, 데이터는 전부 우리 Cloudflare 계정에 쌓입니다.

**사이트가 여러 개여도 대시보드는 하나입니다.** 각 사이트에 같은 집계 코드를 넣고
`SITE` 값만 다르게 적어주면, 대시보드 위쪽 선택 메뉴에서 사이트별로 골라 보거나 한 번에 비교할 수 있습니다.

```
영업 페이지     ┐
그린홈시스 홈페이지 ├→ Cloudflare Worker → D1 데이터베이스
비아블랑 홈페이지  ┘                          ↑
                        관리자 → 대시보드 (비밀번호 로그인)
```

### 사이트 코드

| 사이트 | SITE 값 |
|---|---|
| 영업 페이지 (gh-gp.replit.app) | `ghgp` |
| 그린홈시스 홈페이지 | `home` |
| 비아블랑 홈페이지 | `viablanc` |

## 파일

| 파일 | 설명 |
|---|---|
| `worker.js` | 집계 서버 + 대시보드 화면 (Cloudflare Worker에 붙여넣는 코드) |
| `schema.sql` | 기록이 쌓일 표 구조 |
| `snippet.html` | 다른 사이트(워드프레스 등)에 붙여넣는 집계 코드 |

## 설치 순서 (한 번만, 약 10분)

### 1. 데이터베이스 만들기
1. Cloudflare 대시보드 → 왼쪽 메뉴 **Storage & Databases → D1**
2. **Create database** → 이름 `ghgp-analytics` → 생성
3. 만들어진 DB의 **Console** 탭에 `schema.sql` 의 **내용**(파일 이름이 아니라 SQL 글자)을 붙여넣고 실행
4. **Tables** 목록에 `hits` 가 보이면 성공

### 2. Worker 만들기
1. 왼쪽 메뉴 **Workers & Pages** → **Create** → **Workers** → **Start with Hello World!**
2. 이름 `ghgp-stats` → **Deploy**
3. **Edit code** 를 눌러 편집기를 열고, 기존 코드를 전부 지운 뒤 `worker.js` 내용을 붙여넣고 **Deploy**

기본 주소는 `ghgp-stats.<계정>.workers.dev` 형태입니다.
우리 도메인으로 쓰려면 Worker 화면 → **Settings → Domains & Routes → Add → Custom domain** 에서
`dashboard.greenhomesys.com` 을 연결합니다. (해당 도메인의 DNS가 Cloudflare에서 관리되고 있어야 합니다.)
연결 후에도 기존 workers.dev 주소는 함께 동작하므로 중간에 끊기지 않습니다.

### 3. Worker에 설정값 연결
Worker 화면 → **Settings**

**Bindings → Add binding → D1 database**
- Variable name: `DB` ← 반드시 이 이름
- Database: 1번에서 만든 `ghgp-analytics`

**Variables and Secrets → Add**

| 이름 | 종류 | 값 | 필수 |
|---|---|---|---|
| `DASH_PASSWORD` | Secret | 대시보드 로그인 비밀번호 (직접 정하세요) | 필수 |
| `SECRET` | Secret | 아무 무작위 문자열 40자 정도 | 필수 |
| `ALLOW_ORIGIN` | Text | 집계를 허용할 사이트 주소, **쉼표로 구분**<br>예: `https://gh-gp.replit.app,https://greenhomesys.com` | 필수 |
| `SITE_NAMES` | Text | 사이트 코드와 표시 이름<br>예: `ghgp=영업 페이지,home=그린홈시스 홈페이지,viablanc=비아블랑 홈페이지` | 선택 |
| `EXCLUDE_IPS` | Text | 집계에서 뺄 회선(사무실 등), 쉼표로 구분<br>예: `121.130.5.77,210.99.4.` | 선택 |

> `DASH_PASSWORD` 와 `SECRET` 은 누구에게도 알려주지 마세요. 설치를 돕는 사람에게도 필요 없는 값입니다.

저장 후 **Deploy** 를 한 번 더 누릅니다.

### 4. 사이트에 집계 코드 켜기
각 사이트 HTML 맨 아래 집계 코드에서 두 줄을 채웁니다.

```js
var ENDPOINT = 'https://dashboard.greenhomesys.com/collect';  // Worker 주소 + /collect
var SITE = 'ghgp';   // 이 사이트를 구분할 이름
```

- `ENDPOINT` 는 모든 사이트가 **같은 주소**를 씁니다.
- `SITE` 만 사이트마다 다르게: 영업 페이지 `ghgp`, 그린홈시스 홈페이지 `home`, 비아블랑 홈페이지 `viablanc`
- `ALLOW_ORIGIN` 에 그 사이트 주소를 추가하는 것도 잊지 마세요. 빠지면 기록이 거부됩니다.

`ENDPOINT` 가 비어 있으면 집계 코드는 아무 일도 하지 않으므로, 설정 전까지 사이트에 아무 영향이 없습니다.

## 집계 코드를 넣을 수 없는 곳 (네이버 블로그, 리틀리 등)

네이버 블로그·리틀리처럼 **남의 플랫폼 위에 있는 페이지에는 집계 코드를 넣을 수 없습니다.**
그 서비스들이 외부 스크립트 삽입을 막아두기 때문입니다. 그래서 "블로그 방문자 수"는 이 대시보드에
나오지 않고, 각 서비스가 제공하는 자체 통계 화면에서 보셔야 합니다.

대신 **거기서 우리 사이트로 얼마나 넘어왔는지**는 정확히 집계할 수 있습니다.
링크 끝에 `?from=` 표시를 붙여두면 됩니다.

| 링크를 거는 곳 | 이렇게 링크 |
|---|---|
| 네이버 블로그 | `https://gh-gp.replit.app/?from=blog` |
| 리틀리 | `https://gh-gp.replit.app/?from=littly` |
| 인스타그램 | `https://gh-gp.replit.app/?from=insta` |
| 카카오톡·문자 | `https://gh-gp.replit.app/?from=kakao` |
| 명함 QR코드 | `https://gh-gp.replit.app/?from=card` |

대시보드의 "유입 경로"에 각각 **네이버 블로그 / 리틀리 / 인스타그램 / 카카오톡 / 명함 QR** 로 표시됩니다.
표시된 이름은 방문자가 사이트 안에서 페이지를 옮겨 다녀도 유지됩니다.

> 네이버·리틀리는 유입 정보를 넘겨주지 않는 경우가 많아, 이 표시를 붙이지 않으면
> "직접 접속"으로 뭉뚱그려 집계됩니다. 링크를 새로 걸 때 습관처럼 붙여두시면 좋습니다.

## 사이트를 나중에 추가할 때

1. `snippet.html` 내용을 새 사이트의 `</body>` 앞에 붙여넣고 `SITE` 값만 새로 정합니다
2. Worker 설정의 `ALLOW_ORIGIN` 에 새 사이트 주소를 쉼표로 이어 붙입니다
   (`www` 주소로도 접속된다면 그 주소까지 함께)
3. `SITE_NAMES` 에 표시 이름을 추가합니다 (선택)

데이터베이스나 Worker를 새로 만들 필요는 없습니다.

### 워드프레스 사이트에 넣기

관리자 화면에서 **테마 파일을 직접 고치지 말고** 아래 중 한 가지 방법을 쓰세요.
테마를 고치면 테마가 업데이트될 때 코드가 사라집니다.

**방법 A — 코드 삽입 플러그인 (권장)**
1. 플러그인 → 새로 추가 → `WPCode` 또는 `Header Footer Code Manager` 검색 후 설치·활성화
2. 새 코드(Snippet) 추가 → 종류는 **HTML** 또는 **Universal**
3. `snippet.html` 내용을 붙여넣고, 위치를 **Footer(본문 끝)** 로 지정
4. 활성화 후 저장

**방법 B — 테마에 코드 삽입 칸이 있는 경우**
외모 → 사용자 정의하기(또는 테마 설정)에 "추가 코드 / 푸터 스크립트" 칸이 있으면 거기에 붙여넣습니다.

넣은 뒤 사이트를 시크릿 창으로 열어보고, 대시보드에 그 사이트가 나타나는지 확인하세요.

## 사용법

- **대시보드 주소**: Worker 주소 그대로 (예: `https://dashboard.greenhomesys.com`)
- 비밀번호를 넣으면 12시간 동안 로그인이 유지됩니다. 검색엔진에는 노출되지 않습니다.

### 조회 기간
화면 오른쪽 위에서 고릅니다.

| 선택 | 그래프 한 칸 | 자동 새로고침 |
|---|---|---|
| 실시간 (최근 5분) | 5분 | 15초 |
| 최근 1시간 | 5분 | 30초 |
| 최근 12시간 | 1시간 | 1분 |
| 최근 24시간 | 1시간 | 2분 |
| 최근 7일 / 30일 / 90일 | 하루 | 없음 |

짧은 기간을 보고 있으면 화면을 켜둔 채로 두어도 알아서 갱신됩니다.
상단에 마지막 갱신 시각이 표시됩니다.

### 보이는 항목
- 오늘 방문자·조회수(항상 오늘 0시 기준), 선택 기간의 방문자·조회수, 추이 그래프
- **사이트별 비교** (사이트가 둘 이상일 때 자동 표시)
- 페이지별 조회수
- 유입 경로 (네이버·블로그·숨고·구글·직접 접속 등)
- 버튼·자료 클릭 (전화, 포인트 서비스, 카탈로그·시스템창호 열람, 자료 다운로드, 블로그·숨고 클릭, 견적/거래처 문의, 영상 재생)
- 기기 비율(모바일/PC), 시간대별 방문 분포

### 우리 직원 방문을 집계에서 빼기

방법 두 가지를 같이 쓰면 대부분 걸러집니다.

**① 사무실 회선 통째로 제외 (권장 · 한 번만 설정)**

사무실 와이파이·유선으로 접속하는 **모든 직원의 모든 기기**가 한 번에 제외됩니다.

1. 사무실에서 대시보드에 접속하면 화면 맨 아래에 `지금 접속한 회선: 000.000.0.00` 이 표시됩니다
2. 그 주소를 Worker 설정의 `EXCLUDE_IPS` 에 넣고 **Deploy**
3. 다시 접속했을 때 "지금 접속한 회선은 집계에서 제외되어 있습니다" 로 바뀌면 완료

> 인터넷 회선 주소는 통신사에 따라 가끔 바뀝니다. 바뀌면 다시 넣어주셔야 하는데,
> 끝자리를 점으로 잘라 `210.99.4.` 처럼 넣어두면 그 대역 전체가 제외되어 덜 번거롭습니다.
> 숫자가 갑자기 늘었다 싶으면 대시보드 아래 표시를 한 번 확인해 보세요.

**② 개인 기기 제외 (휴대폰 데이터 등 사무실 밖 접속용)**

직원들에게 아래 링크를 한 번씩 열어달라고 하세요. 기기마다 한 번이면 됩니다.

```
https://gh-gp.replit.app/?notrack=1
```

열면 화면 위에 "이 기기의 방문은 앞으로 집계되지 않습니다" 안내가 잠깐 뜹니다.
되돌리려면 `?notrack=0` 으로 열면 됩니다.
(브라우저 저장 공간을 청소하면 해제되므로, 그때는 다시 한 번 열어야 합니다.)

**참고**: 검색엔진 로봇은 처음부터 자동 제외됩니다.

## 개인정보 처리

- **IP 주소를 저장하지 않습니다.** 방문자 구분용 임시 식별자를 만들 때만 잠깐 쓰이고, 되돌릴 수 없는 해시로 바꾼 뒤 버립니다.
- 이 식별자는 **날짜가 바뀌면 초기화**되므로 날짜를 넘겨 같은 사람을 추적할 수 없습니다.
- 방문자에게 쿠키를 심지 않습니다. (관리자 로그인 쿠키만 예외)
- 이름·연락처 등 개인을 특정할 수 있는 정보는 일절 수집하지 않습니다.

## 비용

Cloudflare 무료 요금제 범위 안에서 동작합니다.
(Worker 하루 10만 요청, D1 하루 500만 행 읽기 — 사이트 몇 개를 합쳐도 여유가 큽니다.)

### "읽은 행"이 한도에 찼다고 나올 때

방문자가 많아서가 아닙니다. 대시보드 조회 방식 때문입니다. 두 가지를 확인하세요.

**1) 대시보드 탭을 닫으세요.** 실시간·1시간 화면은 자동으로 새로고침합니다.
켜둔 채 잊으면 배경에서 계속 조회합니다. (지금은 탭이 보이지 않으면 멈추도록
고쳐 두었지만, 안 보는 탭은 닫는 편이 확실합니다.)

**2) 인덱스가 있는지 확인하세요.** 조회는 전부 `ts`(기록 시각) 범위로 찾는데,
그 인덱스가 없으면 조회 한 번에 표 전체를 훑습니다. D1 콘솔(Console)에서
아래를 실행하면 됩니다. 이미 있으면 아무 일도 일어나지 않습니다.

```sql
CREATE INDEX IF NOT EXISTS idx_hits_event_ts      ON hits (event, ts);
CREATE INDEX IF NOT EXISTS idx_hits_site_event_ts ON hits (site, event, ts);
```

한도는 **하루 단위로 초기화**되므로, 넘겼더라도 다음 날이면 다시 조회됩니다.
집계 기록(쓰기)은 한도가 훨씬 넉넉해서 그동안에도 계속 쌓입니다.

## 참고

- Replit Growth 탭의 숫자와는 집계 기준이 달라 값이 조금 다를 수 있습니다. 둘 다 정상입니다.
- 숨고 리뷰 수, 네이버 블로그 조회수처럼 다른 회사 사이트 안의 숫자는 외부에서 가져올 수 없어 이 대시보드에 자동 표시되지 않습니다.

## 가견적서 ("견적서 받기") 설치

영업 페이지에 "견적서 받기" 메뉴가 추가되었습니다. 로그인이 없는 사이트라, 고객은
**휴대폰 번호 + 문자 인증번호**로 본인 가견적서만 보고, 마음에 걸리는 부분을 체크합니다.
관리자는 기존 대시보드 비밀번호 그대로 `/quotes` 화면에서 전체 목록을 보고 새 가견적서를 보냅니다.

이 기능은 기존 Worker·D1 을 그대로 씁니다 — 새 서비스를 따로 만들 필요가 없습니다.

### 1. 표 추가하기 (한 번만)

D1 데이터베이스(`ghgp-analytics`)의 **Console** 탭에서 `schema.sql` 파일의 **새로 추가된
아래쪽 부분**(`quotes`, `quote_otp` 표)을 붙여넣고 실행합니다. 이미 있는 `hits` 표는
그대로 둔 채 새 표만 추가되므로, 기존 방문 집계에는 영향이 없습니다.

### 2. Worker 코드 갱신

`worker.js` 전체 내용을 Worker **Edit code** 화면에 다시 붙여넣고 **Deploy** 합니다.
(집계 코드와 대시보드 코드가 같은 파일에 들어 있어, 매번 전체를 통째로 바꿔치기합니다.)

### 3. 문자 발송 설정값 추가

Worker **Settings → Variables and Secrets** 에 아래를 추가합니다.

| 이름 | 종류 | 값 | 필수 |
|---|---|---|---|
| `PPURIO_ACCOUNT` | Secret | 비즈뿌리오 계정 아이디 | 문자 실제 발송 시 필수 |
| `PPURIO_API_KEY` | Secret | 비즈뿌리오 API 키 | 문자 실제 발송 시 필수 |
| `PPURIO_FROM` | Text | 문자 발신번호 (비즈뿌리오에 사전 등록된 번호) | 문자 실제 발송 시 필수 |
| `QUOTE_TEST_MODE` | Text | `1` 로 두면 실제 문자를 보내지 않고, 인증번호를 화면에 그대로 보여줍니다 | 테스트할 때만 |

> `PPURIO_API_KEY` 도 `DASH_PASSWORD`·`SECRET` 과 마찬가지로 누구에게도 알려주지 마세요.

**먼저 테스트 모드로 확인하세요.** 비즈뿌리오 계정을 아직 연결하지 않았거나, 연결했어도
한 번 검증하고 싶다면 `QUOTE_TEST_MODE` 를 `1` 로 켜 두고 배포합니다. 이 상태에서는
"인증번호 받기"를 눌러도 실제 문자가 나가지 않고, 화면에 `(테스트) 인증번호: 123456`
처럼 바로 보여줘서 전체 흐름(가견적서 등록 → 고객 조회 → 체크 저장)을 문자 없이 확인할 수 있습니다.

확인이 끝나면 `PPURIO_ACCOUNT`/`PPURIO_API_KEY`/`PPURIO_FROM` 을 채우고
`QUOTE_TEST_MODE` 는 **반드시 지운 뒤** 다시 Deploy 하세요. 지워져 있으면 평소처럼
꺼진 상태(실제 문자 발송)로 동작합니다.

> ⚠ 문자 발송(비즈뿌리오 `POST /v3/message`) 요청 형식은 공개된 예시를 바탕으로
> 최선을 다해 만들었지만, 이 환경에서 비즈뿌리오 문서 사이트 접속이 막혀 있어
> 실제 응답으로 확인하지는 못했습니다. 실제 계정 연결 후 "인증번호 받기"를 한 번
> 테스트해 보시고, 문자가 안 오면 알려주세요 — 비즈뿌리오 관리자 화면의 "API 연동
> 가이드"에 있는 최신 예시로 `worker.js` 의 `sendOtpSmsViaPpurio` 함수 하나만
> 고치면 됩니다(다른 부분은 손댈 필요 없습니다).

### 4. 영업 페이지에 `quote.html` 반영

`quote.html` 은 `index.html`/`archive.html`/`reviews.html` 과 같은 자리(저장소 최상위)에
있어, 평소처럼 **git sync → Republish** 하면 함께 배포됩니다. 메뉴에 "견적서 받기"가
자동으로 추가되어 있습니다.

### 5. 사용법

- **가견적서 보내기**: 대시보드(`/`) 오른쪽 위 "가견적서 →" 를 누르면 `/quotes` 화면으로
  이동합니다. 전화번호·제목을 넣고 가견적서 이미지를 올리면 바로 고객에게 전달됩니다.
  같은 번호로 새로 보내면 이전 가견적서는 자동으로 회수(비활성화)됩니다.
- **고객 화면**: `quote.html` 에서 휴대폰 번호 → 문자 인증번호 입력 → 가견적서 확인,
  순서로 진행됩니다. 인증은 24시간 동안 유지됩니다.
- **회수**: `/quotes` 목록에서 "회수" 버튼을 누르면 고객은 더 이상 볼 수 없지만,
  기록은 관리자 화면에 그대로 남습니다.
